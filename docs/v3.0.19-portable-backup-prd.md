## 0. 原始需求复述（逐字保留语义）

> 「那我要做到换一台电脑，直接把备份包拖到念语里面就可以一键还原，不需要再考什么密钥。然后再是备份与还原是全局的东西。就是只要你做了备份，然后在另外一台电脑上的念语里面还原，是还原所有的状态，状态与备份机上的念语相同。包括什么聊天记录啦，安装的各种各样的 Skill 啦，还有所有设置啦全都要有。」

用户已选方案：**自动口令短语（一次性记录）** —— 创建备份时软件生成随机口令短语，界面只显示一次并允许复制；跨设备还原时把 `.ny` 拖进念语，输入该口令即可，不需要单独拷密钥文件。

### 主理人已定口径（写进 PRD，不再讨论）

1. 新备份为 `.ny` **v2 容器**：文件中用口令短语派生的密钥**封装主密钥**；**绝不裸放主密钥**。口令短语随机生成（建议 24 位 base32 或 6 个单词，架构定），创建备份时只显示一次并给复制按钮，关闭后不可再次查看。
2. 还原：拖拽 `.ny` 到主窗口（**小窗也要支持**）→ 识别 v2 容器 → 弹出**软件内自绘对话框**（严禁 `window.confirm/prompt/alert`）输入口令 → 解封主密钥 → 解密还原。设置页文件选择器还原路径同样要支持口令输入。
3. 兼容：v1 `.ny`（v3.0.18 生成、无内嵌密钥）仍按旧方式在**同机**还原；跨设备还原 v1 **仍需旧密钥文件**，使用说明写清。旧明文 ZIP 仍可直接还原，旧 ZIP 转换器仍可用。
4. **全量状态恢复范围**：备份须覆盖并在新机还原到与备份机一致 —— `dataDir` 全部内容（角色、会话、聊天记录、消息图片/视频、记忆、朋友圈、日记与留言摘要、剧情节点、所有设置与模型 Key）；`userData/skills.json` 与技能相关文件；`userData/proactive-nhpp.json`；`userData/custom-sounds/`；`userData/character-runtime/`。**排除** `path-config.json` / `custom-data-path.txt`（机器本地路径），并在文档说明。架构师可细化清单，但不得缩水用户点名的聊天记录 / Skill / 所有设置。
5. 还原保持原有原子四步（校验 → 保留旧数据 → 替换 → 成功后删安全备份）；解封 / 解密失败、口令错误不得清空数据。
6. 版本 bump **3.0.19**，写版本记录、发 tag。i18n 10 处、设置索引、动画分组、主题、文档同步铁律照旧。

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

1. **换机零密钥负担**：用户只需记住/抄下一次性的口令短语，无需拷贝 `nianyu-master.key`，即可在任意新机把 `.ny` 拖进念语完成还原。
2. **全量状态一致**：v2 备份覆盖用户点名的全部状态载体（聊天记录、Skill、所有设置与模型 Key、媒体、记忆、日记等），还原后新机与备份机逐项一致；机器本地路径配置不被误覆盖。
3. **安全与兼容不回退**：主密钥绝不裸放进备份包；解封/解密失败与错误口令绝不触发数据清空；v1 `.ny` / 旧 ZIP 的既有恢复路径与原子安全策略完全保留。

### 2.2 User Stories（5 个场景）

1. 作为**换新电脑的用户**，我希望把 `.ny` 备份拖进念语、输入创建时记下的口令即可一键还原，这样我不必再单独拷贝密钥文件、也不必懂技术细节。
2. 作为**在多个设备上使用念语的用户**，我希望还原后聊天记录、安装的 Skill、所有设置（含模型 API Key）都和备份机一模一样，这样我可以无缝接着用。
3. 作为**创建备份的用户**，我希望软件生成一次性口令并只显示一次、方便我复制保存，这样口令不会被别人在界面上反复看到、我也不会遗漏。
4. 作为**在小窗陪伴模式的用户**，我希望把 `.ny` 拖到小窗也能触发还原，这样我不必切回主窗。
5. 作为**仍持有旧版备份的老用户**，我希望 v1 `.ny` 和旧明文 ZIP 依旧能还原、旧 ZIP 转换器依旧可用，这样升级不会让我历史数据失效。

## 5. 验收标准（Definition of Done，逐条勾选）

1. **v2 容器安全**：十六进制/文本查看备份包找不到主密钥明文或密钥 JSON `key` 字段；口令派生 key 可稳定解封，任意错误口令解封失败。
2. **一次性口令**：创建成功后自绘对话框展示明文口令 + 复制按钮 + “仅显示一次”警示；关闭后全仓 UI/日志/设置无任何再次查看入口；复制有反馈。
3. **跨设备新机模拟（核心）**：在 A 机创建 v2 备份并记下口令 → B 机清空用户数据（含 dataDir 与 userData 四项）→ 把 `.ny` 拖入 B 机念语 → 输入口令 → 自动还原重启 → **逐项比对**：聊天记录（会话数/消息条数/图片视频）、角色、安装 Skill 列表、全部设置与模型 API Key、记忆、朋友圈、日记与留言摘要、剧情节点 —— 与 A 机完全一致。
4. **拖拽主窗**：拖入触发引导层、识别三态、v2 弹自绘口令框；错误口令/损坏包数据目录字节不变、不重启；全程无原生弹窗（代码扫描 `window.prompt/confirm/alert` 为 0）。
5. **小窗拖拽**：按 §7.2 裁决结果验证小窗拖入行为；若架构给出非冻结方案，需实测通过。
6. **设置页还原**：文件选择器选 v2 包同样弹口令框；高版本备份警告 + 二次确认仍生效。
7. **兼容性四态**：v2 / v1 同机 / v1 跨机带密钥 / 旧 ZIP 直还原 / 转换器产物，按 §4.3 矩阵全部通过。
8. **原子与失败保护**：口令错误 / 篡改容器 / 注入中途失败三类变异测试后，原数据 100% 保留、无空目录、无“恢复出厂”；成功路径各安全备份被正确清理。
9. **工程约束**：cursor 链路、MiniChat/ChatWindow/`cursorCoverState` 冻结文件零改动（除 §7.2 裁决明确授权）；i18n 10 处、设置索引、动画分组、14 主题对比度、`scripts/verify-*` 全绿。
10. **版本/文档**：`package.json`=3.0.19，`版本更新记录.md` 有新条目并已发 tag；`使用说明.md §21`、`README.md`、`GuideView.tsx`、`硬编码清单.md` 表述与新机制一致。
